## Work Done

### 0. Aside: browser throttling (2026-09-18)

Jeff asked why the GUI emulator sometimes gets throttled. Answer (no code change):
`Envir.throttle()`/`Timer.delayUntil()` pace the emulator with `setTimeout`, which
browsers clamp to ~1 s in hidden/occluded tabs (the panels are separate popup windows);
the other possible cause is main-thread overload from lamp updates. Suggested launch
flags, a `MessageChannel` yield in `Timer.js`, or an unthrottled mode. Not implemented.

### 2. Discovery: what this interpreter can and can't do

Manual pp. 91-93 documents runtime card reading (`J180`...) but it is **not implemented**
in this port (probe `raven1.ipl`: silent no-op, card left in hopper). Input therefore
has to come from the loader as data lists. Implemented and useful: `J10/J11/J16`
(description lists; `J16` picks an attribute at random **weighted by numeric values** --
a native count-weighted Markov step), `J60/J65/J80`, `J120/J125/J126/J129/J200`, `J116`.

### 3. The generator (`mkdeck.py` -> `raven4.ipl` / `rave.ipl`)

Each word is a regional symbol `Tn` and a describable list; its description list maps
successor -> integer count. Training loop (`G2`) counts each adjacent pair (`J10`, then
`J125` or `J11` with a `J120` copy). Generation (`G1`) is `J16`. Text for output:
alphanumeric data terms hold only 5 chars, so each word is a list of pieces (flag +
4 letters, `+` first / `-` continuation) mapped from `Tn` on a **separate** describable
list `X4`; `G4` prints a word's pieces; `G3` prints the continuation table; `decode.py`
joins the pieces. Options: `[nlines=12] [steps=100] [--lspace=900] [--no-table]
[--no-comments] [--out=]`. `rave.ipl` = same program without the ~211 comment cards.
Result (2 stanzas, 115 tokens, 83 distinct words, default 40000 digits): correct
table (verified counts and 100/100 legal transitions), fluent-ish generated text.
Verified count-weighting on a "the cat sat" corpus (3:1 / 2:1 ratios observed).

### 4. Bugs found

2. **Library routines clobber `W0`-`W2`; `40Wn/30Wn` and `J3n` restore does not restore**

## Architecture Notes / Gotchas for next time

- **Always use the Mod-3-4 decks** for anything that prints numbers/data terms; `J66`
  (whose `CF D6-4` regression is in Mod-3-4) is simply avoided (`J65` is used).
- **Test in the GUI, not only the CLI**: the CLI card reader accepts characters the GUI
  rejects. Cards: uppercase A-Z, 0-9, space, `. ) + $ * - / , ( = @ | } ! "` only.
- Column layout (1-based): TYPE 41, NAME 43, PQ 49-50, SYMB 51-55, symbolic LINK 57,
  integer data-term value right-justified to col 61; type-1 comment cards carry text in
  cols 7-40. Labels must be `9-<digits>`. Region sizes must cover names used
  (`X1` needs a region `X0`). A card to be read at runtime goes after Deck-2.
- Do not rely on `W0`-`W2` surviving library calls. Do not put non-numeric attribute
  values on a list you call `J16` on.
- `--memory 60000` works if a bigger corpus needs it; `L0` = 1100 does not fit in 40000.
- Next: whole poem (~440 words; check core/regions), or chase bug 2.
