## Architecture Notes / Gotchas for next time

- **This interpreter has two distinct kinds of `Jnn` routines**, and it
  matters which one you're debugging:
  - *Internal primitives* -- hand-assembled into the interpreter binary,
    registered via literal `05 JJn,0,0,` / `51 n,len` directives in
    `IPL-V-Interpreter.sps`.
  - *Loaded (library) routines* -- ordinary IPL-V code, bundled in
    `IPL-V-Subroutines.card` under a `SYSTEM SUBROUTINE HEADER CARD`,
    registered into the routine directory dynamically at load time via
    the same mechanism a user program's own routines use.
  Don't conclude "primitive doesn't exist" from the internal dispatch
  table alone -- check the subroutines card too.
- **`--switches 1,2,3,4` on `run1620.mjs` turns on IPL-V's own load-time
  assembly listing and (per the plan doc) subroutine linkage tracing** --
  genuinely useful for reconstructing call chains and load-time symbol
  resolution, distinct from the emulator's own `--trace` instruction
  trace.
- **First confirmed proof that a loaded (non-primitive) IPL-V routine
  works correctly end-to-end**, including a real composite call chain
  and correct list-splice semantics (`simple15.ipl`, `J76`/`J72`/`J101`/
  `J22`/`J21`). Meaningful threshold result for the eventual goal of
  running Logic Theorist, which will lean heavily on loaded library
  routines.
- The harness's own auto-mode safety classifier will block a `git
  commit`/`push` that includes a scanned copyrighted book, even sitting
